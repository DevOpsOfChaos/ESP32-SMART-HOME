Master zuerst flashenFlash the master first

Der Master ist die ESP-NOW↔MQTT Bridge. Ohne ihn können Geräte nichts kommunizieren. Er muss als Erstes laufen. Environment: master_firmware. The master is the ESP-NOW↔MQTT bridge. Without it, devices cannot communicate anything. It must run first. Environment: master_firmware.

Base-Firmware zu eigenem Gerät umschreibenAdapting a base firmware to your own device

Jedes Gerät im Repo folgt demselben Muster: ein schlanker Basistyp (basetypes/) enthält die ganze Funk-, MQTT- und Provisioning-Logik. Das konkrete Gerät (devices/) ergänzt nur noch Hardware-spezifisches: Pins, Sensoren und Konfigurationswerte. Every device in the repo follows the same pattern: a lean base type (basetypes/) contains all the radio, MQTT and provisioning logic. The concrete device (devices/) only adds hardware-specific things: pins, sensors and configuration values.

📁 Basistyp (nicht anfassen)📁 Base type (don't touch)

→ ESP-NOW senden / empfangen
→ MQTT publish / subscribe
→ Setup-Portal (Provisioning)
→ HELLO / HEARTBEAT / STATE / ACK
→ Auto-Light, Cover-Zustandsmaschine
→ Sensor-Recovery, Watchdog

→ PinConfig.h — GPIO-Zuordnung
→ main.cpp — Sensor-Init und Hook-Implementierung
→ Hooks: on_config(), on_sensor(), on_control()

main.cpp Hooks implementierenimplement hooks

Der Basistyp ruft drei Hooks auf die du in main.cpp implementierst:The base type calls three hooks that you implement in main.cpp:

// Wird beim Start aufgerufen: Sensoren initialisieren
void on_config() {
    Wire.begin(PIN_SENSOR_SDA, PIN_SENSOR_SCL, NET_ERL_I2C_CLOCK_HZ);
    bme.begin(NET_ERL_BME280_ADDRESS);
}

// Wird periodisch aufgerufen: Sensorwerte lesen
void on_sensor(SensorData* data) {
    data->temperature = bme.readTemperature();
    data->humidity    = bme.readHumidity();
    data->lux         = veml.readLux();
}

// Wird bei eingehenden MQTT-Befehlen aufgerufen
void on_control(ControlCmd* cmd) {
    if (cmd->type == CMD_RELAY) {
        digitalWrite(PIN_RELAY_1, cmd->relay_state ? HIGH : LOW);
    }
}
